## Build Philosophy

1. **Each phase ships something usable.** No phase leaves the app broken. After any phase, you can demo what you've built.
2. **Infrastructure before features.** Phase 0 sets up the Worker, DO, and D1 so feature work is fast and clean.
3. **Magic moment first.** The headline score on a real server lands at the end of Phase 2 — everything after builds on top.
4. **Test as you go.** The scoring math, the anti-leakage filter, and the SSRF guards each get a unit test in the same task that builds them — these are the components whose silent failure kills the product.
5. **Progressive enhancement.** The report page works as plain server-rendered HTML first; the polling loop is a layer, not a foundation.
6. **Review before proceeding.** Push each completed phase as a PR and let a review agent (e.g. CodeRabbit) review it before starting the next phase. External review catches issues the coding agent won't flag.
7. **Never execute tools.** `tools/call` must not exist anywhere in this codebase. Any task touching the MCP client re-verifies this.
8. **Cost is a feature.** Every task that adds an LLM call also logs its cost. The unit economics are load-bearing.

## Agent Session Guide

### How to Use This Roadmap with Your Coding Agent

1. **Start a session:** Give your coding agent the phase prompt at the beginning of each phase.
2. **Read selectively:** Each phase lists its Reference sections — the specific parts of the PRD and vision doc needed for that phase. The agent should read only those sections, not the entire documents.
3. **Let it work:** The agent reads the roadmap, finds the first unchecked task, implements it, and marks it complete.
4. **One session = one phase (ideally):** Try to complete a full phase in one session for best continuity. If you need to stop, the agent can resume from the last unchecked task.
5. **Push a PR for review:** When a phase is complete, push the work as a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review it before starting the next phase.
6. **Need more context?** If a task references a section not in the phase's Reference sections, the agent should read just that section on demand.

### Phase Review Workflow

Branch per phase: `phase-{N}/{phase-slug}` (e.g. `phase-1/ingest-and-static-pass`). PR title `Phase {N}: {Title}`; body includes the goal, completed task range, and what to verify manually. Let the review agent re-review after addressing feedback; merge only when clean. If you're not using GitHub, skip the PR step — but you give up external review catching bugs the coding agent won't flag; per-task verification still applies.

### Session Tips

- **Don't read everything:** The PRD is large. Each phase's Reference sections tell the agent exactly what to read.
- **Don't skip tasks:** Tasks are ordered intentionally. Skipping creates dependency issues.
- **Verify after each phase:** Run the app after completing a phase (`wrangler dev` locally, then production) before moving on.
- **Update the status line:** After completing tasks, update the header: `**Status:** X/52 tasks complete` and `**Current Phase:** Phase N`.
- **The 7-day mapping:** Phase 0 ≈ day 1 · Phase 1 ≈ day 2 · Phase 2 ≈ days 3–4 · Phase 3 ≈ day 5 · Phase 4 ≈ days 6–7 · Phase 5 = launch week. Full-time sprint per VISION.md § Business constraints.

### Prompt Templates

**Starting a new phase:**
> "Read docs/product-roadmap.md and find the current phase. Read only the Reference sections listed for that phase from docs/prd.md, docs/product-vision.md, and docs/design.md. Start working on the first unchecked task. After completing each task, update the checkbox to [x] in the roadmap file. Continue through the phase."

**Resuming after a break:**
> "Read docs/product-roadmap.md. Find where we left off (first unchecked task). Read only the Reference sections listed for the current phase. Continue from the first unchecked task."

**After completing a phase:**
> "Phase [N] is complete. Create a branch called phase-{N}/{slug}, commit all work, push, and open a PR targeting main. Title it 'Phase {N}: {Title}' and include the phase goal and completed task count in the body."

**Fixing an issue:**
> "There's a problem with [description]. Read the relevant section of docs/prd.md for the expected behavior and fix it. Don't mark any new tasks complete until the fix is verified."
